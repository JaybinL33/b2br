# Born2beRoot 요구사항 감사 — 2026-10-16

**결론:** 현재 기록만으로 전체 요구 충족을 선언할 수 없다. 우선순위는 sudo 그룹의 실제 권한 검증, monitoring 지표의 의미, 평가용 변경 시연과 최종 제출 디스크 확인이다. 반면 고유 사용자 수·used/total 비율·게스트 소켓 수·단일 LUKS 안 여러 LV는 근거 없이 오류로 단정하거나 다른 구현으로 바꾸지 않는다.

- **명시 요구:** 원문 또는 읽을 수 있는 평가표 문구 자체. **해석:** 모호한 문구·예시를 구체화한 선택. **기록 확인:** 실제 수행 당시의 증거. **미검증:** 근거 부족이며 실패 확정이 아님. **확정 오류:** 문서 설명이나 구현의 의미가 근거와 명백히 다른 경우.
- 아래 우선순위는 준비 순서이며 점수나 자동 실격 판정이 아니다. 평가자는 당시의 완전한 과제·평가표로 판단한다.

Sudo 집계는 실행마다 한 개의 I/O 세션이 생기고 모두 보관된 범위에서는 명령 실행 횟수의 근거가 될 수 있다. 로깅 도입 전 실행·삭제된 세션·로깅 예외는 복원하지 못한다. sudo로 연 셸 내부의 모든 하위 명령을 별도 sudo 실행으로 세는 것도 아니다. 과제는 “시스템 수명 전체”라는 기간을 지정하지 않는다. 따라서 무조건 영구 누적 시스템을 새로 만들 필요는 없지만, 현재 보관 목록과 요구한 실행 횟수의 범위가 같다는 설명·검증은 필요하다. journal 전체 행 수로 바꾸면 서비스 메시지·회전·중복 등 다른 오류가 생기므로 대안이 자동으로 더 정확하지 않다.

원문은 오류가 표시되지 않아야 한다고 요구한다. 현재 단순 코드는 vmstat 입력이 비면 100%, 수집 명령 실패 뒤 wc가 0을 만들 수 있다. 고정 표본 시험으로 이 한계는 재현되지만 사용자 VM에서 해당 실패가 발생했다는 증거는 아니다. 정상 실행 출력의 성공도 모든 실패 상황의 처리를 증명하지 않는다. 이번 감사는 승인된 단순 코드에 방어 옵션·함수를 일괄 추가하지 않았다.

## 이번 교정과 다음 실행 순서

이번에는 모호한 지표를 다른 해석으로 몰래 바꾸지 않고, 사용자명 검사 예외와 비밀번호 차이 계산의 설명을 보완했다. 현재 코드 사본·과거 학습 기록·실제 VM 상태는 보존했다. 감사의 미검증을 학습 로그의 실패나 완료로 기록하지 않는다.

1. 현재 설치본 내용은 available 추가 전 승인 코드와 동작상 일치 확인했다. available 추가 적용·수동 방송은 23:48 출력으로 확인했다. 수정 후 bash -n·해시는 미첨부다. sudo 권한 출처 등 남은 정책 증거는 별도로 구분한다.
2. sudo 그룹 정책을 실제 적용하기로 한 시점에 새 사용자 실행·로그를 검증한다. wheel 제거는 이번 감사의 실행 항목이 아니다.
3. 가용량 표시는 적용 확인했으며 sudo 집계 범위의 의미는 별도로 구분한다. users·CPU·df 비율은 정의를 설명하며 원자료와 비교한다.
4. hostname 재부팅 유지·예약 주석 유지·파일 불변은 직접 확인, hostname 복원은 후속 출력 확인, 8080 실습·매분 및 다중 터미널 검증은 사용자 보고 확인이다. 완료된 항목의 반복 검사를 요청하지 않는다.
5. VDI SHA-1 재계산은 확인했다. 이번 계산 당시 Powered Off 여부와 실제 제출 저장소 경로를 사용자에게 질문했으며 답변 대기다. 최종 cron 두 줄 활성 출력, 제출 루트 README·signature.txt 작성, 보존 사본·복원은 미확인으로 유지한다. 실제 제출 루트에서 printf로 해시만 한 줄을 signature.txt에 쓰도록 안내했으나 실행 결과는 없다.

이 순서는 향후 사용자 실습을 위한 제안이다. 본 감사는 설정 변경·새 계정 생성·암호 시험·로그 삭제·VM 부팅·디스크 복사·학교 저장소 제출을 수행하지 않았다.
