# Born2beRoot v5.2 — 요구사항 정리와 평가 체크리스트

이 문서는 원문 `en.subject.pdf`의 요구사항을 작업 순서와 평가 항목에 맞춰 재구성한 정리본입니다. 전체 문장과 예시는 [한국어 전체 번역](Born2beRoot-v5.2-ko-full.md)을 참고하세요. **「해설」이나 「권장 점검」으로 표시한 부분은 이해와 검증을 돕는 설명이며, 원문에 추가된 필수 요구사항이 아닙니다.**

## 3. 필수 요구사항 체크리스트

### 가상 머신·운영체제·디스크

- [ ] VirtualBox를 사용한다. 사용할 수 없는 경우 UTM을 사용한다.
- [ ] Debian 또는 Rocky Linux의 최신 안정 버전을 설치했다.
- [ ] 그래픽 서버를 설치하지 않았다.
- [ ] 서버에 필요한 최소한의 서비스를 구성했다.
- [ ] LVM을 이용해 최소 2개의 암호화된 파티션을 구성했다.
- [ ] 파티션 크기를 정한 이유를 설명할 수 있다.
- [ ] Debian: AppArmor가 부팅 시 실행된다.
- [ ] Rocky: SELinux가 부팅 시 실행되며 과제에 맞게 설정되어 있다.

Rocky의 KDump 설정은 필요하지 않습니다. 필수 파티션 그림의 예시 구조는 다음과 같습니다.

```text
가상 디스크
├─ /boot
└─ 암호화 장치
   └─ LVM
      ├─ /      (루트 파일 시스템)
      ├─ swap   (스왑)
      └─ /home  (사용자 홈)
```

**해설:** 위 구조는 원문 그림을 단순화한 것입니다. 그림은 암호화 계층 안에 LVM 논리 볼륨을 배치합니다. 예시의 디스크 크기를 그대로 사용할 의무는 없습니다.

### SSH·방화벽

- [ ] SSH 서비스가 4242번 포트에서 실행된다.
- [ ] root 계정으로 SSH 접속할 수 없다.
- [ ] Debian에서는 UFW, Rocky에서는 firewalld를 사용한다.
- [ ] 기본 필수 구성에서는 4242번 포트만 열려 있다.
- [ ] 방화벽은 가상 머신 부팅 시 활성화된다.
- [ ] 평가 중 생성한 새 사용자로 SSH 사용을 확인할 수 있다.

보너스 서비스가 있는 경우에는 필요한 추가 포트를 열 수 있습니다. 이에 맞춰 방화벽 규칙도 조정해야 합니다.

### 호스트명·사용자·그룹

- [ ] 호스트명은 `<내 로그인 이름>42` 형식이다. 예: `wil42`.
- [ ] root 외에 내 로그인 이름과 같은 사용자명이 존재한다.
- [ ] 해당 사용자는 `user42` 그룹에 속한다.
- [ ] 해당 사용자는 `sudo` 그룹에 속한다.
- [ ] 평가 중 호스트명을 바꿀 수 있다.
- [ ] 평가 중 새 사용자를 만들고 그룹에 추가할 수 있다.

### 비밀번호 정책

| 요구사항 | 값 또는 규칙 | root 적용 |
|---|---|---|
| 만료 주기 | 30일 | 적용 |
| 변경 사이 최소 간격 | 2일 | 적용 |
| 만료 사전 경고 | 7일 전 | 적용 |
| 최소 길이 | 10자 | 적용 |
| 문자 구성 | 대문자 + 소문자 + 숫자 | 적용 |
| 동일 문자 연속 | 최대 3자; 4자 이상 연속 금지 | 적용 |
| 사용자명 포함 | 금지 | 적용 |
| 이전 비밀번호와의 차이 | 이전 비밀번호에 없던 문자 최소 7개 | **이 항목만 예외** |

- [ ] 위 정책을 구성했다.
- [ ] 구성 후 root를 포함해 가상 머신의 모든 계정 비밀번호를 변경했다.
- [ ] 정책의 각 숫자와 root 예외를 설명할 수 있다.

**해설:** “동일 문자가 3자를 초과하여 연속해서는 안 된다”는 같은 문자가 3번 연속하는 것까지 금지한다는 뜻이 아닙니다. 같은 문자 4개 이상의 연속이 금지됩니다. 원문은 특수문자를 별도의 필수 조건으로 요구하지 않습니다.

### sudo 정책

| 항목 | 요구사항 |
|---|---|
| 인증 시도 | 잘못된 비밀번호 입력 시 최대 3회 |
| 오류 메시지 | 직접 정한 메시지를 표시 |
| 로그 범위 | 수행한 작업의 입력과 출력 모두 |
| 로그 위치 | `/var/log/sudo/` |
| 터미널 | TTY 모드 활성화 |
| 실행 경로 | sudo에서 사용할 경로 제한 |

원문의 경로 예시:

```text
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin
```

- [ ] sudo를 설치하고 위 정책을 설정했다.
- [ ] 입력·출력 로그가 실제로 남는지 확인했다.
- [ ] 경로 제한과 TTY 설정의 의미를 설명할 수 있다.

## 4. monitoring.sh 요구사항

| 동작 | 요구사항 |
|---|---|
| 파일명 | `monitoring.sh` |
| 언어 | Bash |
| 실행 시점 | 서버 시작 시, 이후 10분마다 |
| 전달 대상 | 모든 터미널 |
| 참고 도구 | 방송은 `wall`, 실행 예약은 `cron`을 살펴볼 것 |
| 배너 | 선택 사항 |
| 오류 출력 | 표시되어서는 안 됨 |
| 평가 시 | 동작 설명 및 스크립트 수정 없이 중단 가능해야 함 |

### 표시할 정보 12개

| 번호 | 정보 | 원문 예시의 표시명 |
|---|---|---|
| 1 | 운영체제 아키텍처와 커널 버전 | `Architecture` |
| 2 | 물리 프로세서 수 | `Physical CPU` |
| 3 | 가상 프로세서 수 | `vCPU` |
| 4 | RAM의 현재 사용 가능량 및 사용률 | `Memory Usage` |
| 5 | 저장 공간의 현재 사용 가능량 및 사용률 | `Disk Usage` |
| 6 | 현재 CPU 사용률 | `CPU load` |
| 7 | 마지막 재부팅 날짜와 시간 | `Last boot` |
| 8 | LVM 활성 여부 | `LVM use` |
| 9 | 활성 연결 수 | `TCP Connections` |
| 10 | 서버 사용 사용자 수 | `User log` |
| 11 | IPv4 주소 및 MAC 주소 | `Network` |
| 12 | sudo로 실행한 명령 수 | `Sudo` |

**원문 표현 차이:** 본문은 RAM·저장 공간의 “사용 가능한” 양을 요구하지만, 예시는 사용량/전체 용량을 보여줍니다. 연결 수 예시는 TCP의 `ESTABLISHED` 연결 수입니다. 전체 번역에 본문과 출력 예시를 모두 보존했으므로, 실제 구현 시 적용되는 평가 기준도 함께 확인하세요.

### 권장 점검

- [ ] 12개 정보가 빠짐없이 표시된다.
- [ ] 부팅 직후 실행과 10분 간격 실행을 모두 확인했다.
- [ ] 여러 터미널에서 방송을 확인했다.
- [ ] 오류가 터미널에 나타나지 않는다.
- [ ] 값을 어떻게 구하고 계산하는지 설명할 수 있다.
- [ ] 스크립트를 고치지 않고 예약 실행을 중단할 수 있다.

## 5. README 작성 요구사항

README는 저장소 **루트**에 둡니다. 영어를 권장하지만 캠퍼스의 주된 언어도 허용됩니다.

첫 줄은 이탤릭체로 다음 문구를 사용합니다. 로그인 이름을 실제 값으로 바꿉니다.

```markdown
*This project has been created as part of the 42 curriculum by <login1>[, <login2>[, <login3>[...]]].*
```

한 명이 참여한 경우의 형식 예시:

```markdown
*This project has been created as part of the 42 curriculum by your_login.*
```

| 구성 요소 | 반드시 포함할 내용 |
|---|---|
| `Description` | 프로젝트 목표와 개요 |
| `Instructions` | 관련 설치·실행 정보, 필요한 경우 컴파일 정보 |
| `Resources` | 문서·기사·튜토리얼 등 참고 자료와 AI 사용 내역 |
| 프로젝트 설명 | 운영체제 선택 이유와 양쪽의 장단점 |
| 주요 설계 결정 | 파티션, 보안 정책, 사용자 관리, 설치 서비스 |
| 비교 1 | Debian vs Rocky Linux |
| 비교 2 | AppArmor vs SELinux |
| 비교 3 | UFW vs firewalld |
| 비교 4 | VirtualBox vs UTM |

AI 사용 내역에는 **어떤 작업에, 프로젝트의 어느 부분에 사용했는지** 명시해야 합니다. 이 한국어 번역과 요구사항 정리도 실제 사용 내역에 해당할 수 있습니다.

| 보너스 | 내용 |

## 7. 제출과 서명 관리

### 제출물

```text
저장소 루트/
├─ README.md
└─ signature.txt
```

원문 IV장은 `signature.txt`만 언급하지만, VI·VIII장은 `README.md`도 명확히 요구합니다. 두 파일을 준비하세요. VM 디스크 파일은 Git에 넣지 않습니다.

### 서명 대상과 명령

**가상 디스크 파일의 SHA-1**을 사용합니다. VirtualBox는 `.vdi`, UTM은 `.qcow2`가 대상입니다. 과제 PDF, 설정 파일, VM 폴더 자체의 해시를 쓰는 것이 아닙니다.

| 플랫폼 | 기본 위치 | 원문 명령 예시 |
|---|---|---|
| Windows | `%HOMEDRIVE%%HOMEPATH%\VirtualBox VMs\` | `certUtil -hashfile rocky_serv.vdi sha1` |
| Linux | `~/VirtualBox VMs/` | `sha1sum rocky_serv.vdi` |
| Mac M1·UTM | `~/Library/Containers/com.utmapp.UTM/Data/Documents/` | `shasum rocky.utm/Images/disk-0.qcow2` |
| macOS·VirtualBox | `~/VirtualBox VMs/` | `shasum rocky_serv.vdi` |

원문의 예시 해시는 다음과 같지만, **본인의 서명으로 사용하면 안 됩니다.**

```text
6e657c4619944be17df3c31faa030c25e43e40af
```

### 권장 제출 순서

1. VM 구성과 자체 점검을 마칩니다.
2. VM을 종료해 디스크 내용이 바뀌지 않는 상태로 둡니다.
3. 실제 디스크 파일의 SHA-1을 구합니다.
4. 해시 문자열을 `signature.txt`에 기록합니다.
5. README와 서명을 확인합니다.
6. 이후 VM을 다시 실행했다면 디스크 서명이 변경되었을 수 있으므로 다시 확인합니다.

**해설:** 위 순서는 디스크 내용 변경으로 인한 불일치를 피하기 위한 권장 절차입니다. 원문은 VM 재시작 시 서명이 바뀐다고 경고하며, 디스크 복제 또는 평가용 스냅샷 활용을 언급합니다.

### 스냅샷 규칙

```text
평가 시작 전: 스냅샷 없음
        ↓
평가 시작 후: 해당 평가용 스냅샷 생성
        ↓
평가 종료: 해당 스냅샷 삭제
```

프로젝트 제출 전에 스냅샷 기능을 시험해 보는 것은 원문에서 권장합니다. 평가 시작 시 스냅샷이 없어야 한다는 규칙은 별도로 지켜야 합니다.

## 8. 권장 작업 순서

다음 순서는 요구사항을 효율적으로 확인하기 위한 정리이며, 원문이 지정한 유일한 작업 순서는 아닙니다.

| 단계 | 작업 | 확인할 결과 |
|---|---|---|
| 1 | 원문 읽기·도구·OS 결정 | VirtualBox/UTM과 최신 안정 OS 선택 |
| 2 | 디스크 설계·OS 설치 | 암호화 LVM, 최소 서비스, 그래픽 서버 없음 |
| 3 | 호스트명·사용자·그룹 설정 | `<login>42`, `<login>`, `user42`·`sudo` |
| 4 | 비밀번호·sudo 정책 적용 | 숫자 조건, root 예외, TTY·경로·로그 |
| 5 | SSH·방화벽·보안 모듈 구성 | 4242, root SSH 금지, 부팅 시 활성화 |
| 6 | monitoring.sh 작성·예약 | 시작 시 + 10분마다 전체 터미널에 12개 정보 |
| 7 | 재부팅·기능 점검·설명 연습 | 서비스·정책·모니터링 유지, 질문 대응 |
| 8 | 필요하면 보너스 구성 | 필수 기능 유지, 추가 포트 확인 |
| 9 | README·실제 디스크 서명 준비 | 두 제출 파일, 해시 일치, 스냅샷 상태 |

## 9. 원문에 있는 점검 명령

아래 명령은 **과제 VM 안에서** 관련 권한으로 실행하는 점검용 예시입니다. 설정 완료를 보장하는 명령은 아니며, 출력이 요구사항을 충족하는지 확인해야 합니다.

### Debian

```bash
head -n 2 /etc/os-release
/usr/sbin/aa-status
ss -tunlp
/usr/sbin/ufw status
```

### Rocky

```bash
head -n 2 /etc/os-release
sestatus
ss -tunlp
firewall-cmd --list-service
firewall-cmd --list-port
firewall-cmd --state
```

**주의:** 원문의 화면은 Debian 10과 Rocky 8.7 예시입니다. 설치해야 하는 버전은 최신 안정 버전입니다. Rocky 화면에는 `ssh` 서비스 허용이 나오는데, 기본 서비스 정의가 22/tcp를 열 수도 있습니다. 화면 출력을 그대로 따라 하기보다 본문의 “4242만 개방” 조건과 실제 방화벽 설정을 대조하세요.

**권장 점검:** 서비스 상태만 확인하지 말고, 새 일반 사용자로 실제 SSH 접속이 되는지, root SSH 접속이 거절되는지, 재부팅 후에도 요구 서비스가 살아 있는지 확인하세요.
