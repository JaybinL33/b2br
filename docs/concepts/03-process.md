# 프로그램·프로세스·서비스

[개념 지도](../concepts.md) · 먼저 읽기: [운영체제](01-os.md)

## 프로그램과 프로세스

**프로그램**은 실행할 명령을 담은 파일이고, **프로세스**는 그 프로그램을 실행 중인 한 사례다. 같은 `/bin/bash`를 두 터미널에서 열면 프로그램 파일은 같아도 프로세스는 둘이다. 각각 자신의 변수, 현재 디렉터리, 열린 파일과 실행 상태를 가질 수 있다.

커널은 프로세스를 구별하기 위해 **PID(process ID)**라는 번호를 준다. PID는 실행 중인 대상을 찾는 표지이지 프로그램의 영구 이름이 아니다. 종료한 프로세스의 번호는 나중에 재사용될 수 있다. 새 프로세스를 만든 쪽은 부모이고 새로 만들어진 쪽은 자식이다. 셸이 외부 명령을 실행하면 대체로 자식 실행 흐름을 만들고, 그 안에서 원하는 프로그램을 실행한다. 셸 내장 명령처럼 별도 프로세스 없이 처리하는 경우도 있다.

CPU가 하나여도 여러 프로세스가 번갈아 실행되면 동시에 진행되는 것처럼 보인다. 커널의 **스케줄러**가 실행 기회를 나눈다. 프로세스가 디스크나 입력을 기다리는 동안 다른 프로세스가 CPU를 쓸 수 있다. CPU를 기다리는 상태와 I/O를 기다리는 상태는 다르므로 “느리다”가 항상 “CPU가 부족하다”는 뜻은 아니다. 한 프로세스 안에서 작업 흐름을 나누는 **스레드**는 메모리 등 많은 자원을 공유한다. 스레드 수와 프로세스 수, 가상 CPU 수는 다른 수치다.

## 만들기·교체·전환·통신

**fork**는 현재 프로세스를 바탕으로 자식 프로세스를 만드는 호출이다. 처음에 비슷한 메모리 내용을 보지만 이후 변경은 독립적으로 관리하며 COW가 복제 비용을 줄일 수 있다. **exec** 계열은 현재 프로세스의 실행 내용을 다른 프로그램으로 교체한다. 새 프로세스를 하나 더 만드는 일과 구분되므로, 셸이 자식을 만든 뒤 명령 프로그램으로 바꾸는 흐름을 두 단계로 이해할 수 있다.

**문맥 교환(context switch)**은 CPU가 실행하던 흐름의 상태를 보관하고 다른 흐름의 상태로 전환하는 작업이다. 여러 작업을 진행하게 하지만 전환과 캐시 영향에는 비용이 있다. **전경 작업**은 터미널의 입력·제어 신호와 연결된 작업이고, **백그라운드 작업**은 셸이 그 작업의 종료만 기다리지 않고 다음 입력을 받을 수 있게 하는 실행 방식이다. 백그라운드로 보냈다고 systemd가 관리하는 서비스가 되거나 로그아웃 뒤 생존이 보장되지는 않는다.

**IPC(프로세스 간 통신)**는 분리된 실행 흐름이 정보를 주고받는 수단의 총칭이다. 파이프·소켓·공유 메모리 등이 서로 다른 방식으로 이를 제공한다. **공유 메모리**는 여러 프로세스가 같은 메모리 영역에 접근하게 해 데이터 복사 비용을 줄일 수 있지만 접근 순서를 맞출 필요가 있다. **경쟁 상태(race condition)**는 실행 순서에 따라 결과가 달라지는 문제다. 두 실행 흐름이 같은 카운터의 이전 값을 읽고 각각 1을 더해 저장하면 한 번의 증가가 사라질 수 있다.

**뮤텍스(mutex)**는 공유 자원을 한 번에 한 실행 흐름이 사용하도록 상호 배제를 제공하는 동기화 수단이다. **교착 상태(deadlock)**는 각 작업이 다른 작업이 가진 자원을 기다려 모두 진행할 수 없는 상태다. A가 잠금 1을 가진 채 2를 기다리고 B는 2를 가진 채 1을 기다리는 예가 있다. 잠금을 사용했다는 사실만으로 순서와 해제 설계까지 올바른 것은 아니다.

## 시그널과 종료

**시그널(signal)**은 프로세스에 사건을 알리는 통지다. 예를 들어 터미널에서 Ctrl+C를 누르면 보통 전경 작업의 프로세스 그룹에 SIGINT가 전달된다. 프로그램이 종료 요청을 받았을 때 파일을 닫고 상태를 저장할 수 있도록 SIGTERM 같은 신호를 처리할 수 있다. SIGKILL은 프로그램이 붙잡아 처리할 수 없으므로 정리 코드를 실행할 기회를 주지 않는다.

따라서 “프로세스를 없앤다”와 “서비스를 정상 종료한다”는 결과가 같지 않을 수 있다. SSH 서버나 로그 프로그램을 갑자기 끝내면 연결이나 쓰기 작업이 끊길 수 있다. 프로세스가 종료되면 부모는 종료 결과를 받아 자식의 정보를 정리한다. 아직 결과가 수거되지 않은 종료 프로세스를 **좀비**라고 부른다. 좀비는 계속 CPU를 사용하며 일하는 프로세스와 다르다.

## 서비스, 데몬, systemd

**서비스(service)**는 시스템이 지속적으로 제공하거나 관리하는 기능이다. 원격 접속, 방화벽 관리, 예약 실행이 예다. **데몬(daemon)**은 보통 사용자의 대화형 명령 입력 없이 요청이나 사건을 기다리는 백그라운드 프로그램이다. sshd와 crond가 대표적이다. 모든 서비스가 영구 실행 데몬인 것은 아니다. 한 번 준비 작업을 마치고 끝나는 서비스도 있다.

**systemd**는 이 VM에서 부팅 후 시스템을 구성하고 서비스를 관리하는 프로그램이다. 시스템 관리자는 PID 1로 실행되며, 관리 대상을 **unit**이라는 단위로 표현한다. `.service`는 서비스 실행, `.mount`는 마운트, `.timer`는 시간에 따른 실행을 표현한다. **target**은 여러 unit을 특정 목적 아래 묶는 단위다. `multi-user.target`은 여러 사용자가 사용할 기본 서버 환경과 연결되며 그래픽 로그인 환경을 뜻하지 않는다.

`sshd.service`는 실행할 프로그램, 시작 조건과 종료 방식 등을 연결한다. systemd는 그 서비스에 속한 프로세스들을 관리하므로 PID 하나만 보고 서비스 전체를 판단하지 않는다. **active**는 현재 unit 상태이고 **enabled**는 부팅 등의 시작 경로에 연결해 둔 상태다. 지금 실행 중이지만 다음 부팅에 자동 시작하지 않는 서비스도 가능하다.

설정 파일을 바꾸는 일과 실행 중인 프로그램에 다시 읽히는 일도 구분해야 한다. unit 자체를 바꿨다면 systemd가 unit 정의를 다시 읽어야 하고, sshd_config를 바꿨다면 sshd가 자신의 설정을 다시 읽어야 한다. 이 차이가 `daemon-reload`, 서비스 `reload`, 프로세스를 다시 시작하는 `restart`의 차이로 이어진다. 우리 VM에서는 systemd가 sshd·firewalld·crond를 관리하고, crond가 다시 monitoring 작업을 시작한다.
