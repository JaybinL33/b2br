# 서버 서비스·예약 실행·시간

[개념 지도](../concepts.md) · 먼저 읽기: [프로세스와 systemd](03-process.md), [셸](04-shell.md), [네트워크](11-network.md)

## 서버는 요청과 상태를 다룬다

**클라이언트–서버 구조**는 요청하는 쪽과 기능을 제공하는 쪽을 나누는 방식이다. 서버는 반드시 큰 물리 장비를 뜻하지 않는다. 같은 컴퓨터 안에서도 클라이언트와 서버 프로세스가 통신할 수 있다. **프로토콜**은 이들이 메시지의 형식과 순서·의미를 공유하는 약속이다. 포트가 열려 있어도 서로 다른 프로토콜을 말하면 서비스 이용에 성공하지 못한다.

**동시성**은 여러 작업의 진행이 겹치는 성질이고, **병렬성**은 실제로 여러 작업을 동시에 수행하는 성질이다. CPU 하나에서도 요청 A의 I/O를 기다리는 동안 B를 처리하면 동시성을 만들 수 있다. **블로킹 I/O**는 요청한 입출력이 준비될 때까지 호출한 실행 흐름이 기다리는 방식이다. **이벤트 루프**는 준비된 사건을 받아 처리하고 다시 기다리는 구조로, 많은 연결을 처리하는 서버에서 쓰인다. 무거운 계산 하나로 루프를 오래 점유하면 다른 요청의 응답도 늦어질 수 있다.

**프록시**는 통신 중간에서 요청을 대신 전달하는 구성 요소다. **리버스 프록시**는 서버 앞에서 클라이언트 요청을 받아 내부 서버로 전달한다. **로드 밸런서**는 여러 처리 대상에 요청을 분배한다. 한 프로그램이 두 역할을 함께 할 수 있지만 전달 위치와 분배 기능이라는 관점은 다르다. 이 VM의 필수 SSH 구성에 이를 추가한다는 뜻은 아니며 서버 구조를 넓게 이해하는 연결 개념이다.

**상태 저장 서비스**는 이전 작업의 데이터나 세션 상태가 이후 동작에 영향을 주는 서비스다. **무상태 처리**는 요청을 처리하는 인스턴스가 이전 요청의 로컬 상태에 의존하지 않도록 설계하는 방식이다. 데이터가 세상 어디에도 없다는 뜻이 아니라 외부 데이터베이스 등에 상태를 맡길 수 있다는 뜻이다. 그래서 서버 프로세스를 다시 시작하는 것과 서비스 데이터를 지우는 것은 구분해야 한다.

## 설정을 읽고 적용하는 단계

**설정 파일**은 프로그램의 동작 선택을 실행 코드와 분리해 표현한다. **설정 우선순위**는 여러 파일·명령 인자·환경값이 같은 항목을 정할 때 어떤 값이 유효한지의 규칙이다. 마지막 줄이 항상 이기는 것은 아니며 프로그램마다 첫 값·마지막 값·누적 방식이 다르다. SSH처럼 포함 파일과 조건부 구역이 있는 설정은 실제 적용 문맥까지 읽어야 한다.

**reload**는 실행 중인 서비스에 설정을 다시 읽히는 요청이고, **restart**는 서비스를 멈추고 새로 시작하는 요청이다. reload 지원 여부와 기존 연결에 미치는 영향은 서비스마다 다르다. **daemon-reload**는 systemd가 unit 정의를 다시 읽도록 한다. sshd_config를 편집한 경우와 sshd.service의 unit 설정을 편집한 경우가 서로 다른 작업으로 이어지는 이유다.

**소켓 활성화**는 systemd 등이 먼저 통신 소켓을 준비하고 필요할 때 서비스를 시작해 그 소켓을 넘기는 방식이다. 서비스 프로세스가 아직 없다는 사실만으로 수신 경로가 없다고 단정할 수 없는 사례다. **재시작 정책**은 비정상 종료 같은 조건에 따라 서비스를 다시 시작할지 정한다. 반복 재시작은 가용성을 도울 수 있지만 잘못된 설정을 고치지는 않으므로 시작 실패 원인과 함께 봐야 한다.

**멱등성(idempotency)**은 같은 작업을 반복 적용해도 의도한 최종 상태가 달라지지 않는 성질이다. 설정 파일에 같은 줄을 계속 추가하는 작업은 중복이 쌓이지만 “이 값이 정확히 한 번 존재하게 한다”는 작업은 반복 실행에 견디게 만들 수 있다. **구성 관리**는 원하는 상태를 기록하고 실제 상태를 맞추는 방식이다. 명령 실행 이력과 원하는 최종 상태는 서로 다른 정보다.

## 사람 없이 실행하는 작업

**cron**은 시간표에 맞춰 작업을 시작하는 스케줄러다. **crontab**은 그 시간표를 담는 표다. 사용자 crontab은 해당 사용자 자격으로 실행하며 시스템 crontab 형식에는 실행 사용자 칸이 추가될 수 있다. 형식을 섞으면 시간표가 맞아도 의도한 명령으로 해석되지 않는다. 이 프로젝트는 root의 사용자 crontab에서 monitoring을 시작하는 구성을 쓴다.

**달력 기반 스케줄**은 시각·요일 같은 벽시계 조건으로 실행한다. cron의 `*/10` 분 조건은 매시간 0·10·20…분에 맞추며 “이전 작업이 끝난 뒤 10분”을 뜻하지 않는다. 이전 실행이 오래 걸리면 다음 실행과 겹칠 수 있다. **작업 잠금**은 동시에 실행하면 안 되는 작업의 중복 수행을 막는 수단이다. 예약 주기와 단일 실행 보장은 별도의 설계 문제다.

**systemd timer**는 시간 조건을 unit으로 표현해 관련 서비스를 시작한다. 달력 시각뿐 아니라 부팅 후 경과 시간 등으로도 예약할 수 있다. 놓친 달력 실행을 이후에 보완하는 옵션도 있지만 설정과 시간 조건에 따라 달라진다. 현재 과제에서 요구한 cron을 timer로 바꾼다는 뜻은 아니며, 운영체제가 제공하는 다른 시간 실행 모델을 비교하는 내용이다.

## 시각과 경과 시간을 구분한다

**벽시계 시간(realtime)**은 날짜와 시각을 나타내며 시간 동기화나 관리자 변경으로 조정될 수 있다. **단조 시간(monotonic time)**은 경과 시간 측정을 위해 역행하지 않는 시계를 제공한다. 구현에 따라 절전 시간 포함 여부 등이 다르다. 소요 시간을 벽시계 값의 단순 차이로 계산하면 시각 보정 때문에 결과가 이상해질 수 있다.

**시간대(time zone)**는 같은 순간을 지역의 날짜·시각으로 표시하는 규칙이다. **UTC**는 여러 시스템의 시각을 비교할 때 공통 기준으로 쓰는 시간 척도다. **NTP**는 네트워크로 시계를 동기화하는 프로토콜이며 chrony 같은 구현이 이를 사용한다. 시간대를 바꾸는 것과 실제 시계의 오차를 보정하는 일은 다르다. 로그 시각·인증서 유효기간·예약 작업을 함께 이해하려면 이 차이가 필요하다.
