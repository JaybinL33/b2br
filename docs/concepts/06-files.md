# 파일·경로·마운트

## 파일은 내용이고 이름은 그것을 찾는 경로다

일반 **파일**은 프로그램이 읽고 쓰는 바이트들의 연속이다. 텍스트·이미지·실행 파일이라는 의미는 그 바이트를 해석하는 형식에서 나온다. **디렉터리**는 이름과 파일 객체의 연결을 관리하는 특별한 파일이다. 디렉터리 안에 이름이 있으므로 `/home/jungblee/note`처럼 단계별로 찾아갈 수 있다.

**경로(path)**는 디렉터리 구조에서 대상을 찾는 표현이다. **절대 경로**는 `/`에서 시작하고 **상대 경로**는 프로세스의 현재 작업 디렉터리에서 시작한다. `.`은 현재 디렉터리, `..`는 상위 디렉터리를 나타낸다. **홈 디렉터리**는 사용자의 개인 파일과 설정을 두는 위치다. 로그인 직후 현재 위치가 홈인 경우가 많지만 둘은 같은 개념이 아니다. 다른 폴더로 이동해도 홈 자체가 바뀌지는 않는다.

Linux의 디렉터리 트리는 `/`에서 시작한다. 이 **루트 디렉터리**와 UID 0인 root 사용자, root 사용자의 홈 `/root`는 서로 다르다. `/etc`에는 시스템 설정, `/var`에는 로그·상태 등 변하는 데이터, `/usr`에는 많은 프로그램과 공유 자료를 둔다. 이 관례 덕분에 다른 서버에서도 파일의 역할을 짐작할 수 있지만 실제 저장 위치는 마운트 구성에 따라 달라진다.

## inode와 링크

**inode**는 파일시스템 안에서 파일의 종류·소유자·권한·크기와 데이터 위치 등의 정보를 담는 객체다. 파일 이름은 inode 자체의 이름표라기보다 디렉터리 항목에서 inode로 이어지는 연결이다. 그래서 파일 이름을 바꿔도 그 파일의 데이터 전체를 다른 곳으로 복사해야 하는 것은 아니다. inode 번호는 해당 파일시스템 안에서 해석하며 다른 파일시스템의 같은 번호와 동일 파일이라고 볼 수 없다.

**하드 링크(hard link)**는 같은 파일 객체를 가리키는 다른 디렉터리 항목이다. 두 이름으로 같은 내용을 읽고 고칠 수 있다. 한 이름을 지워도 다른 링크가 남아 있으면 파일은 유지된다. 일반적인 하드 링크는 같은 파일시스템 안에서 만든다. **심볼릭 링크(symbolic link)**는 다른 경로를 가리키는 내용을 가진 별도 파일이다. 다른 파일시스템도 가리킬 수 있지만 대상이 없어지면 끊어진 링크가 된다.

파일을 연 프로세스는 파일 디스크립터를 통해 열린 객체를 계속 참조한다. **unlink**는 디렉터리의 이름 연결을 없애는 작업이다. 마지막 이름을 없앴어도 프로세스가 파일을 열고 있으면 데이터 공간이 즉시 반환되지 않을 수 있다. 로그를 삭제했는데 `df`의 사용량이 그대로인 상황을 이 관계로 이해할 수 있다. 이름 목록에서 없어졌다는 것과 아무도 파일을 사용하지 않는다는 것은 다르다.

## 마운트로 하나의 트리를 만든다

**파일시스템(filesystem)**은 저장 영역을 파일·디렉터리·메타데이터로 조직하는 규칙과 구현이다. **마운트(mount)**는 파일시스템을 디렉터리 트리의 한 위치에 연결하는 작업이고 그 위치가 **마운트 지점**이다. 예를 들어 별도 파일시스템을 `/home`에 마운트하면 사용자는 같은 `/` 아래 경로로 접근하면서 실제로는 다른 저장 영역을 사용한다.

마운트는 폴더 안의 데이터를 옮기는 작업이 아니다. `/var/log` 아래에 파일이 있던 상태에서 다른 파일시스템을 그곳에 마운트하면 아래의 원래 파일들이 가려진다. 마운트를 해제하면 다시 보일 수 있다. 이 때문에 로그 LV가 마운트되지 않은 동안 root 영역에 로그가 쌓이는 상황이 가능하다.

**root 파일시스템**은 `/`의 기반이다. 그 안의 디렉터리에 다른 파일시스템을 붙여 전체 트리를 구성한다. **fstab**은 장치 식별, 마운트 지점, 유형과 옵션 등을 기록한 설정 파일이다. 부팅 구성과 mount 도구가 이를 사용하지만 파일을 편집했다고 현재 마운트가 즉시 바뀌지는 않는다. 현재 연결 상태와 다음 부팅의 설정이 다를 수 있다.

**가상 파일시스템(VFS)**은 서로 다른 파일시스템을 공통 파일 인터페이스로 다루게 하는 커널 계층이다. 앱은 대체로 ext4인지 다른 형식인지에 관계없이 파일 열기·읽기 요청을 한다. **procfs**는 `/proc`에서 프로세스와 커널 정보를 파일처럼 제공하고 **sysfs**는 `/sys`에서 장치·커널 객체의 속성을 제공한다. 이 파일들을 읽는다고 항상 디스크의 일반 파일을 읽는 것은 아니다.

**장치 파일(device file)**은 `/dev`에서 장치와 연결되는 인터페이스다. 블록 장치와 문자 장치 등이 있으며 크기가 있는 일반 문서와 다르게 동작한다. **tmpfs**는 메모리 기반으로 파일을 제공하며 조건에 따라 swap도 이용할 수 있다. 재부팅 뒤 유지할 데이터의 저장소와는 다르다. **sparse 파일**은 긴 0 구간을 실제 저장 블록을 배정하지 않는 hole로 표현할 수 있는 파일이다. 읽으면 같은 0이 나오므로 논리적인 파일 크기와 실제 차지한 공간이 다를 수 있다.

우리 VM의 `/`, `/home`, `/var/log`는 별도 LV 위 ext4를 사용한다. 따라서 `/home`의 여유가 많아도 `/var/log`가 자동으로 그 공간을 빌려 쓰지 않는다. `findmnt`는 연결 관계, `df`는 파일시스템의 사용량, `du`는 경로 아래 파일의 사용량을 살피는 서로 다른 질문의 도구다.

근거: [Linux VFS 개요](https://www.kernel.org/doc/html/latest/filesystems/vfs.html), [Rocky File System](https://docs.rockylinux.org/books/admin_guide/07-file-systems/), [fstab 공식 매뉴얼](https://github.com/util-linux/util-linux/blob/master/sys-utils/fstab.5.adoc). 파일을 읽을 권리는 [사용자와 권한](09-permissions.md)에서 이어진다.

디렉터리별 역할·보존 기간·관리 주체와 실제 b2br 경로는 [Linux 디렉터리 지도](../directories.md)에서 이어진다. 파일의 원리를 반복하기보다 `/etc`·`/usr`·`/var`와 가상 파일시스템을 어떻게 구분해 찾는지 정리했다.
