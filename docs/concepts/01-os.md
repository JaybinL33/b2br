# 운영체제와 Linux 배포판

[개념 지도](../concepts.md)

## 운영체제, 커널, 사용자 공간

컴퓨터에서 여러 프로그램이 동시에 동작하려면 CPU를 언제 누구에게 줄지, 어느 메모리가 누구 것인지, 디스크를 누가 읽고 쓸 수 있는지 정해야 한다. **운영체제(OS)**는 이런 자원 관리와 프로그램 실행 환경을 제공하는 소프트웨어 전체를 가리킨다. 화면이나 명령창만이 운영체제는 아니다.

그 중심의 **커널(kernel)**은 하드웨어를 다루고 프로그램 사이의 경계를 유지한다. 프로그램이 파일을 읽고 싶다고 디스크 장치를 마음대로 조작하는 대신, 커널에 열기·읽기 같은 작업을 요청한다. 이 요청 통로를 **시스템 호출(system call)**이라고 한다. 커널은 대상과 권한을 판단하고 장치 드라이버 등을 통해 작업한다. 드라이버는 저장장치·네트워크 장치처럼 종류가 다른 하드웨어를 다루는 코드다.

**사용자 공간(user space)**은 커널 밖에서 일반 프로그램이 실행되는 영역이다. Bash, `ls`, SSH 서버, 패키지 관리자 모두 여기에 속한다. root 권한으로 실행한 프로그램도 사용자 공간 프로그램일 수 있다. “사용자 공간”은 일반 사용자만 쓴다는 뜻이 아니라 커널과 실행 경계가 다르다는 뜻이다. 프로그램은 보통 서로 분리된 메모리 주소 공간을 가지므로 한 프로그램의 주소가 곧 다른 프로그램의 같은 데이터를 뜻하지 않는다.

Linux라는 이름은 엄밀히는 커널을 가리키지만 일상에서는 그 커널을 사용하는 운영체제 전체를 뜻하기도 한다. **배포판(distribution)**은 Linux 커널에 명령 도구, 라이브러리, 설치기, 패키지 관리, 기본 설정과 업데이트 체계를 묶어 제공한다. Rocky와 Debian은 모두 Linux를 쓰지만 패키지 형식·관리 도구·기본 보안 구성과 지원 정책이 다르다. 그래서 커널 정보를 보여 주는 `uname`과 배포판 정보를 담은 `/etc/os-release`가 서로 다른 질문에 답한다.

이 VM의 Rocky Minimal은 작은 설치 구성을 선택한 것이다. 그래픽 화면이 없더라도 커널·셸·네트워크·서비스는 동작한다. 서버에 필요한 기능을 명령과 설정 파일로 운영할 수 있기 때문에 그래픽 서버 없이도 SSH 서버를 만들 수 있다.

## GNU와 배포판 생태계

**GNU**는 자유롭게 사용·연구·수정·배포할 수 있는 Unix 계열 운영체제를 만들려는 프로젝트다. Bash, Coreutils, GCC, glibc 같은 도구와 라이브러리를 제공한다. Linux 커널만으로 설치기·명령·컴파일러가 모두 생기는 것은 아니다. GNU 도구와 여러 프로젝트의 소프트웨어를 Linux와 조합한 시스템을 GNU/Linux라고 부르는 이유다. Linux 기반 시스템이 모두 같은 사용자 공간을 쓰는 것은 아니므로 Linux와 GNU를 완전히 같은 말로 쓰지는 않는다.

**라이브러리(library)**는 여러 프로그램이 공통으로 사용할 기능을 모은 코드다. 프로그램마다 파일 처리·문자열·네트워크 기능을 전부 새로 만들지 않도록 한다. **API**는 프로그램이 기능을 요청할 때 사용하는 이름·인자·반환 규칙이고, **ABI**는 이미 컴파일된 프로그램이 라이브러리·커널과 주고받는 호출 규약·바이너리 형식 같은 약속이다. 같은 소스라도 다른 CPU용 실행 파일을 그대로 실행하지 못하는 이유에는 명령어 체계와 ABI가 함께 관련된다.

**RHEL(Red Hat Enterprise Linux)**은 Red Hat이 기업 운영과 지원을 위해 제공하는 Linux 배포판이다. 지원 주기와 호환성, 보안 유지보수가 중요하게 다뤄진다. **Rocky Linux**는 기업용 Linux 환경과 RHEL 호환성을 지향하는 커뮤니티 배포판이다. 그래서 RHEL 문서가 좋은 참고가 되지만, 지원 계약·패키지 빌드·발표 시점까지 동일한 제품이라는 뜻은 아니다. 우리 VM에서 RHEL 계열의 DNF·RPM·SELinux·firewalld를 함께 접하는 것은 이 생태계 선택과 연결된다.

**Debian**은 커뮤니티가 만드는 범용 운영체제 배포판으로, 패키지를 통합하고 안정 릴리스를 관리한다. **Ubuntu**는 Debian을 기반으로 발전한 배포판이며 Canonical과 커뮤니티가 개발·지원한다. Debian과 Ubuntu가 `.deb`·APT 생태계를 공유해도 저장소와 패키지를 무분별하게 섞을 수 있는 것은 아니다. 배포판은 파일 모음뿐 아니라 어떤 조합을 함께 시험하고 유지할지 정하는 체계이기 때문이다.

**upstream**은 소프트웨어의 원 개발 프로젝트, **downstream**은 이를 가져와 배포판이나 제품에 통합하는 쪽을 뜻한다. 관계에 따른 말이므로 어느 프로젝트가 항상 한쪽인 것은 아니다. 예를 들어 배포판은 OpenSSH의 downstream으로 패치를 적용하고, 조직 내부 서버 이미지는 그 배포판의 downstream이 될 수 있다.

**안정 릴리스(stable release)**는 배포판이 운영용으로 관리하는 릴리스다. 이름의 “안정”은 절대 오류가 없다는 약속이 아니라 버전·변경 정책을 통해 예측 가능한 조합을 제공한다는 의미에 가깝다. **LTS**는 장기 지원 정책을 가리키며 정확한 기간·대상 패키지는 배포판마다 다르다. 최신 upstream 버전 번호가 아니어도 보안 수정을 기존 버전에 옮겨 적용할 수 있다. 이 방식을 [패키지 장](13-packages.md)에서 backport와 연결한다.

**오픈 소스 라이선스**는 소스를 볼 수 있다는 사실을 넘어 사용·수정·배포에 어떤 권리와 조건이 있는지 정한다. 같은 시스템 안의 커널·명령·라이브러리가 서로 다른 라이선스를 가질 수 있다. 서버를 운영하는 것과 변경한 소프트웨어를 재배포하는 것은 검토할 조건이 달라질 수 있다.
