# 전원에서 로그인까지의 부팅

[개념 지도](../concepts.md) · 먼저 읽기: [저장장치](07-storage.md), [프로세스](03-process.md)

## 운영체제보다 먼저 실행되는 코드

**펌웨어(firmware)**는 장치에 가까운 곳에 저장되어 하드웨어 초기화 등을 수행하는 소프트웨어다. 컴퓨터 전원을 켜면 운영체제보다 먼저 실행되어 메모리·장치 상태를 준비하고 부팅할 대상을 찾는다. 초기 하드웨어 점검을 **POST**라고 부른다. 펌웨어 화면조차 나오지 않는 문제와 Linux 서비스가 시작되지 않는 문제는 서로 다른 단계의 문제다.

**BIOS**와 **UEFI**는 PC 부팅 펌웨어의 서로 다른 방식이다. 전통적 BIOS 부팅은 디스크의 부트 코드에서 다음 단계를 이어 간다. UEFI는 펌웨어의 부팅 항목을 통해 EFI 실행 파일을 시작할 수 있고, 디스크의 **EFI System Partition(ESP)**에 그런 부팅 파일을 둔다. BIOS+GPT에서 쓰는 **BIOS Boot 파티션**은 GRUB의 일부 코드를 둘 공간으로, 파일시스템을 가진 ESP나 `/boot`와 같은 것이 아니다.

우리 설계는 BIOS+GPT와 별도 `/boot`를 사용한다. 이는 하나의 선택이며 UEFI보다 Linux에 본질적으로 더 맞는다는 뜻은 아니다. VirtualBox가 제공하는 가상 펌웨어도 이 역할을 수행하므로 VM의 EFI 옵션 변경은 단순 화면 취향이 아니라 부팅 방식과 연결된다.

## 부트로더와 초기 Linux 환경

**부트로더(bootloader)**는 커널을 메모리에 올리고 실행을 넘기는 프로그램이다. **GRUB**은 여러 커널·운영체제 중 부팅할 항목을 고를 수 있게 하는 부트로더다. 커널 업데이트 뒤 이전 커널 항목으로 부팅할 수 있는 것은 이런 선택 구조 덕분이다. GRUB 설정과 실제 실행 중인 커널은 별개이며 메뉴에 보인다는 것만으로 그 커널이 실행된 것은 아니다.

**커널 명령줄(kernel command line)**은 커널과 초기 부팅 환경에 넘기는 매개변수다. root 장치, 콘솔 등 초기 설정을 알려 준다. 이 시점에는 일반적인 root 파일시스템을 아직 사용할 수 없을 수 있다. 초기 환경이 필요한 이유는 root 자체가 암호화되었거나 LVM·특정 드라이버 뒤에 있기 때문이다.

**initramfs**는 커널과 함께 메모리에 준비하는 초기 파일·도구 묶음이다. 실제 root를 여는 데 필요한 프로그램·드라이버·설정을 제공한다. Rocky의 **dracut**은 이런 초기 부팅 이미지를 만드는 도구다. initramfs 안에서 저장장치를 찾고 LUKS를 열고 LV를 사용할 수 있게 한 다음, 실제 root 파일시스템으로 실행 기반을 옮긴다. 이 전환을 **switch root**라고 한다. 배포판 구성에 따라 초기 환경에서도 systemd를 쓸 수 있다.

따라서 `/etc`의 저장장치 설정을 바꿨을 때 실행 중 시스템의 파일만 달라지고 initramfs에는 이전 정보가 남는 경우를 생각할 수 있다. 초기 부팅에 영향을 주는 설정과 평상시 서비스 설정의 적용 시점을 구분하는 이유다. LUKS 암호 입력 화면에서 대기한다면 일반적으로 아직 사용자 SSH 로그인 단계까지 도달하지 않은 것이다.

## systemd가 사용할 시스템을 구성한다

실제 root로 전환한 뒤 systemd는 마운트·장치·네트워크·서비스·로그인 통로를 준비한다. **의존성(dependency)**은 어떤 대상이 다른 대상을 필요로 하는 관계이고, **순서(ordering)**는 어느 작업 뒤에 시작할지 정하는 관계다. A가 B 뒤에 시작한다는 선언만으로 B를 반드시 시작시키는 것은 아니다. 필요한 연결과 순서가 맞아야 준비가 끝나기 전에 서비스를 실행하는 문제를 줄일 수 있다.

**default target**은 기본적으로 도달하려는 unit 묶음이다. 서버의 `multi-user.target`과 그래픽 로그인을 포함하는 `graphical.target`은 시스템이 제공할 환경이 다르다. 콘솔 로그인은 터미널에 로그인 프롬프트를 제공하는 **getty**와 인증 흐름을 거쳐 셸로 이어진다. sshd를 통한 원격 로그인은 네트워크와 서버 프로세스를 거치는 별도 입구다.

**rescue 모드**와 **emergency 모드**는 제한된 상태에서 시스템을 복구하기 위한 실행 환경이다. 어떤 서비스·마운트가 준비되는지는 다르므로 정상 로그인 환경과 같은 도구·네트워크가 모두 있다고 생각하지 않는다. **Secure Boot**는 부팅 코드의 서명을 검증하는 신뢰 연결과 관련된다. 디스크 내용을 암호화하는 LUKS와는 보호 목적이 다르다. 하나는 무엇을 실행할지의 신뢰, 다른 하나는 저장 내용을 누가 읽을 수 있는지와 연결된다.

부팅 장애를 이해하는 핵심은 한 번에 “Linux가 고장났다”라고 묶지 않는 것이다. 펌웨어 → 부트로더 → 커널·initramfs → root 전환 → 마운트·서비스 → 로그인 중 마지막으로 성공한 단계가 다음 질문을 정한다.
