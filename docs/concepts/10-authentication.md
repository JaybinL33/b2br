# PAM·비밀번호·계정 정책

[개념 지도](../concepts.md) · 먼저 읽기: [인증과 인가](09-permissions.md)

## 응용프로그램마다 인증을 다시 만들지 않도록

SSH, 콘솔 로그인, sudo는 모두 사용자 신원이나 계정 상태를 확인할 필요가 있다. 각 프로그램이 로컬 비밀번호, 외부 계정 서버, 만료 검사 등을 모두 직접 구현하면 정책을 바꾸기 어렵다. **PAM(Pluggable Authentication Modules)**은 이런 프로그램과 인증 관련 구현 사이에 공통 호출 구조를 제공한다. 프로그램이 “이 사용자를 인증해 달라”거나 “세션을 시작한다”고 요청하면 설정에 연결된 모듈들이 작업한다.

**PAM 모듈**은 하나의 역할을 수행하는 구성 요소다. 로컬 계정 정보를 이용하는 모듈, 비밀번호 품질을 검사하는 모듈, 세션 자원을 준비하는 모듈 등이 있다. 여러 모듈을 순서와 판단 규칙으로 연결한 것이 **PAM 스택**이다. 이것은 비밀번호 정책 파일 한 개와 같지 않다. 어떤 프로그램이 어느 서비스 이름으로 PAM을 호출하며 어떤 스택을 거치는지가 실제 적용 범위를 결정한다.

PAM은 네 종류의 처리를 구분한다. **auth 처리**는 신원 증명을 확인하고, **account 처리**는 인증한 계정이 만료되지 않았는지 등 사용 가능 조건을 판단한다. **password 처리**는 비밀번호 등 인증 토큰을 변경하며, **session 처리**는 로그인 전후에 환경·기록·자원 관련 작업을 한다. 비밀번호가 맞는데도 만료 계정이 로그인하지 못하는 상황은 auth와 account가 다른 일을 하기 때문에 가능하다.

스택의 **제어 플래그**는 각 모듈 성공·실패를 전체 결과로 어떻게 합칠지 정한다. `required`는 실패를 최종 결과에 반영하면서 뒤 작업을 계속할 수 있고, `requisite` 실패는 즉시 실패로 돌아가는 방식이다. `sufficient` 성공은 앞선 필수 실패가 없는 등의 조건에서 뒤 처리를 생략할 수 있다. 따라서 줄 순서와 플래그는 단순 장식이 아니라 정책의 실행 흐름이다.

우리 VM의 passwd는 system-auth의 password 스택으로 이어지고, pam_pwquality가 새 비밀번호를 검사한 뒤 pam_unix가 로컬 갱신을 수행한다. `use_authtok`는 앞 단계에서 받은 새 토큰을 다음 모듈이 재사용하도록 하는 연결이다. 검사와 저장을 분리하면서 같은 새 비밀번호를 처리하는 것이다. **authselect**는 이런 공통 인증 구성을 프로필과 선택 기능으로 관리하는 도구다. 생성된 파일을 직접 고치면 프로필에서 다시 생성할 때 변경을 잃을 수 있어 관리 방식과 적용 파일을 함께 이해해야 한다.

## 비밀번호는 어떻게 저장하고 검사하는가

비밀번호를 파일에 평문으로 저장하면 파일 유출이 곧 모든 비밀번호 유출이 된다. 그래서 시스템은 일반적으로 입력한 비밀번호로 **비밀번호 해시**를 계산해 저장된 값과 비교한다. 해시는 같은 입력에서 같은 결과를 얻지만 결과에서 원래 입력을 쉽게 되돌리지 못하도록 쓰는 변환이다. 저장된 해시 자체가 유출되면 공격자가 추측한 비밀번호를 계산해 대조할 수 있으므로 해시라고 공개해도 되는 것은 아니다.

**salt**는 같은 비밀번호라도 다른 저장값이 나오도록 계산에 추가하는 값이다. 미리 계산한 결과표를 여러 계정에 그대로 재사용하기 어렵게 한다. **비밀번호 KDF**는 추측 한 번의 계산에 의도적인 시간·메모리 비용을 부여하는 함수다. 일반 파일 체크섬을 빠르게 계산하는 목적과 비밀번호 추측을 비싸게 만드는 목적은 다르다. yescrypt 같은 저장 방식은 이런 맥락에서 등장한다.

**shadow 파일**은 로컬 계정의 암호 해시와 기간 정보를 제한된 접근 권한으로 보관한다. 해시 저장 방식은 PAM·배포판 구성과 연결된다. SSH 호스트 키나 LUKS 키는 이 shadow 비밀번호 해시와 서로 다른 자격 정보다. 같은 “암호”라는 말로 모두 묶으면 어떤 값을 바꿀 때 어떤 접근이 달라지는지 놓치게 된다.

## 품질, 기간, 잠금은 다른 조건이다

**비밀번호 품질 정책**은 새로 정하는 비밀번호가 길이·문자 구성·유사성 조건을 만족하는지 검사한다. **비밀번호 만료 정책**은 이미 설정된 비밀번호를 언제 바꿔야 하는지 정한다. **계정 만료**는 계정 자체를 사용할 수 있는 기간이고, **계정 잠금**은 특정 인증 방법의 사용을 막는 상태와 연결된다. 예를 들어 비밀번호 해시를 잠가도 다른 인증 방법까지 항상 전부 막힌다고 볼 수는 없다.

libpwquality의 `minlen`, 문자 credit, `maxrepeat`, `usercheck`, `difok`는 품질의 서로 다른 조건이다. `difok`는 이전·새 비밀번호 사이의 변경을 비교하므로 이전 비밀번호를 얻는 경로가 필요하다. 사용자가 자신의 passwd를 실행하는 것과 관리자가 다른 사용자의 비밀번호를 재설정하는 것은 이 점에서 다르다. root의 `enforce_for_root`는 품질 거절을 적용하지만 root가 이전 암호를 입력하지 않는 경로의 비교를 자동 복구하지 않는다.

`login.defs`는 계정 생성 도구가 사용할 기간 기본값 등을 제공한다. 기존 계정의 실제 기간은 계정별 정보이므로 `chage`가 다룬다. 품질 설정을 바꿔도 이미 저장된 비밀번호가 자동 교체되지 않고, 기본 만료값을 바꿔도 모든 기존 계정에 소급 적용되지 않는다. 우리 정책의 최소 2일·최대 30일·7일 경고는 서로 “너무 자주 변경하지 않기”, “최장 사용 기간”, “교체 준비 시간”이라는 다른 시점을 다룬다.

**MFA(다중 요소 인증)**는 비밀번호 같은 지식 외에 보유 장치 등 다른 종류의 증명을 결합한다. **중앙 계정 서비스**는 여러 서버가 계정 정보를 공유하도록 하는 구조이며 LDAP·AD 같은 시스템이 이 맥락에서 등장한다. **SSSD**는 Linux에서 이런 외부 계정·인증 제공자와 연결하고 캐시하는 역할을 할 수 있다. 이들은 PAM의 프로그램별 호출과 NSS의 계정 조회에 함께 연결될 수 있지만 현재 local 프로필과 동일한 구성은 아니다.
