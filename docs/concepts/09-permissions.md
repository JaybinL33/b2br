# 사용자·그룹·권한과 sudo

[개념 지도](../concepts.md) · 먼저 읽기: [파일](06-files.md), [프로세스](03-process.md)

## 이름보다 숫자로 소유권을 연결한다

**사용자 계정**은 프로그램 실행과 데이터 접근의 주체를 구분하는 시스템의 기록이다. 사람이 로그인하는 계정도 있고 서비스를 위해 쓰는 계정도 있다. 커널은 주로 **UID**라는 숫자로 사용자를 식별한다. 이름 jungblee는 사람이 읽기 쉬운 표지이고, 파일 소유권과 프로세스 자격에는 숫자가 연결된다. 계정을 지웠다가 같은 이름으로 다시 만들어도 UID가 달라지면 이전 파일의 소유자로 자동 취급되지 않을 수 있다.

**그룹**은 여러 사용자에게 같은 접근 조건을 적용하기 위한 묶음이며 숫자 식별자가 **GID**다. 사용자는 **기본 그룹** 하나와 여러 **보조 그룹**에 속할 수 있다. 새 파일의 그룹은 일반적으로 프로세스의 그룹 자격과 부모 디렉터리 설정에 영향을 받는다. 그룹 데이터베이스를 바꿔도 이미 실행 중인 프로세스의 보조 그룹 목록은 즉시 교체되지 않아 새 로그인이 필요한 경우가 생긴다.

`/etc/passwd`는 로컬 계정의 UID·GID·홈·로그인 셸 등을, `/etc/group`은 그룹 정보를 담는다. 실제 조회는 **NSS(Name Service Switch)**를 통해 로컬 파일뿐 아니라 다른 계정 제공자로 이어질 수 있다. 그래서 `getent`가 묻는 “시스템이 알고 있는 계정”과 로컬 파일 한 개의 내용은 범위가 다를 수 있다.

## 파일 권한은 요청 주체와 작업을 함께 판단한다

전통적인 Unix **파일 모드**는 소유자·그룹·기타에 대해 읽기·쓰기·실행 권한을 표현한다. 일반 파일의 읽기는 내용을 읽는 것, 쓰기는 내용을 바꾸는 것, 실행은 프로그램으로 실행할 수 있는 조건과 연결된다. 디렉터리의 실행 비트는 그 경로를 통과하거나 이름을 통해 항목에 접근하는 권리다. 따라서 최종 파일의 읽기 권한이 있어도 부모 디렉터리를 통과하지 못하면 읽을 수 없다.

숫자 표기 755는 소유자가 읽기·쓰기·실행, 그룹과 기타는 읽기·실행을 가진다는 뜻이다. 권한을 바꾸는 **chmod**와 소유자를 바꾸는 **chown**은 다른 속성을 바꾼다. monitoring 파일을 root 소유 755로 두면 일반 사용자가 읽고 실행할 수 있지만 그 코드를 수정할 수는 없다. 다만 코드 안에서 읽는 sudo 로그까지 일반 사용자에게 자동 허용되는 것은 아니다.

**umask**는 새 파일·디렉터리를 만들 때 요청한 권한에서 어떤 권한을 제외할지 정한다. 이미 존재하는 파일의 모드를 일괄 변경하지 않는다. **ACL**은 소유자·한 그룹·기타라는 기본 구분을 넘어 특정 사용자나 그룹의 권한을 추가로 표현한다. 둘 다 접근 설정과 관련되지만 하나는 생성 시 기본 제한, 다른 하나는 대상 파일의 확장 접근 규칙이다.

**setgid**를 디렉터리에 두면 새 항목의 그룹 상속에 활용할 수 있다. **sticky bit**는 여러 사용자가 쓸 수 있는 디렉터리에서 남의 파일을 삭제·이름 변경하는 것을 제한하는 데 쓰인다. `/tmp` 같은 공유 공간이 대표적인 맥락이다. **setuid**가 있는 실행 파일은 실행 시 파일 소유자의 자격을 사용하는 동작과 관련되며 강한 권한 경계가 된다. 모든 파일에 이런 비트를 붙이는 것은 편의 설정이 아니라 보안 모델의 변경이다.

## root, 인증, 인가

**root**는 전통적으로 UID 0인 관리 계정이다. 많은 일반 권한 검사를 우회할 수 있어 시스템 전체를 바꿀 수 있다. Linux의 **capability**는 이런 특권을 작업 종류별로 나누어 일부만 부여할 수 있게 한다. 예를 들어 어떤 프로그램이 한 종류의 특권만 필요할 때 모든 root 권한을 줄 필요를 줄인다. SELinux 같은 정책은 특권 프로세스에도 별도의 제약을 둘 수 있다.

**인증(authentication)**은 주장하는 신원이 맞는지 확인하는 과정이고, **인가(authorization)**는 확인된 주체가 요청한 일을 해도 되는지 결정하는 과정이다. 비밀번호로 로그인에 성공한 사용자라도 다른 사람의 파일을 읽을 권리는 없을 수 있다. 반대로 사용자 이름을 안다는 사실은 신원 증명이 아니다.

**최소 권한 원칙**은 작업에 필요한 만큼만 권한을 주는 운영 원칙이다. 서버에서 일상 작업은 일반 계정으로 하고 관리 작업만 올리는 이유다. **sudo**는 정책에 따라 명령을 다른 사용자 자격으로 실행하는 통로다. sudoers가 누가·어디서·누구 자격으로·어떤 명령을 실행할 수 있는지 정하고 필요한 인증과 기록을 연결한다. sudo는 단순히 모든 명령 앞에 붙이는 root 접두사가 아니다.

**su**는 다른 사용자로 전환하는 셸·명령 실행과 관련되고, sudo는 허용 정책과 호출자 인증·감사를 중심으로 운영할 수 있다. 어느 도구를 썼는지에 따라 인증 대상과 환경이 다를 수 있다. 우리 구성의 wheel은 관리자 권한 규칙과 연결되고 user42·sudo 그룹은 과제에서 요구한 멤버십이다. 그룹 이름이 sudo라는 이유만으로 그 그룹에 권한이 생기는 것은 아니다.

sudo의 **secure_path**는 sudo 실행 환경에서 명령 검색 경로를 제한한다. 절대 경로로 지정한 모든 명령의 허용 목록은 아니다. **TTY 요구**는 대화형 터미널이 있는 호출을 요구하는 조건이고, **I/O 로깅**은 명령의 입력·출력을 기록하는 기능이다. 신원 확인, 명령 허용, 환경 제한, 기록은 각각 다른 단계이므로 한 설정으로 나머지를 대신할 수 없다.
