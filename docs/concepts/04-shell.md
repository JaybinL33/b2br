# 셸·터미널·입출력

[개념 지도](../concepts.md) · 먼저 읽기: [프로세스](03-process.md)

구체적인 옵션·자료 처리 도구는 [명령어 중심 참조](../commands.md#텍스트-처리와-탐색), 셸 문법과 외부 명령의 경계는 [명령줄 읽기](../commands.md#명령줄을-읽는-기준)에서 찾는다.

## 셸과 터미널은 서로 다른 역할이다

**셸(shell)**은 명령을 읽어 해석하고 실행하는 프로그램이다. Bash는 셸의 한 종류다. 명령 이름과 인자를 나누고, 변수를 확장하고, 입출력을 연결한 다음 프로그램을 실행한다. **터미널(terminal)**은 사람이 입력하고 프로그램 출력을 받는 통로다. 화면에 보이는 터미널 앱과 그 안에서 실행되는 Bash는 서로 다른 프로그램이다.

**TTY**는 이러한 터미널 통로를 운영체제가 다루는 장치 인터페이스다. VM 콘솔의 `tty1`처럼 직접 로그인하는 통로와, 터미널 앱이나 SSH가 만드는 **의사 터미널(PTY)**이 있다. `pts/0` 같은 이름은 PTY의 한쪽을 나타낸다. 사용자 이름이 같아도 서로 다른 터미널 세션일 수 있다. TTY는 글자를 표시하는 것 외에 입력 줄 처리와 Ctrl+C 같은 제어 동작에도 관여한다.

cron에서 실행되는 작업은 사람과 연결된 터미널이 없어도 실행될 수 있다. 반대로 sudo에 `requiretty`를 설정하면 그런 통로 없는 sudo 호출은 거절될 수 있다. root cron에서 monitoring 내부에 다시 sudo를 넣지 않는 구성은 이미 root인 실행 주체와 TTY 조건을 함께 생각한 결과다.

## 표준 입출력과 파이프

프로세스는 열린 입출력 통로를 **파일 디스크립터**라는 작은 번호로 참조한다. 관례적으로 0은 **표준입력(stdin)**, 1은 **표준출력(stdout)**, 2는 **표준오류(stderr)**다. 대화형 프로그램에서는 입력이 키보드, 출력이 터미널일 수 있지만 반드시 그래야 하는 것은 아니다. 셸은 파일이나 다른 프로세스를 이 통로에 연결할 수 있다.

**리다이렉션**은 통로의 대상을 바꾼다. `>`는 표준출력을 파일로 보내며 기존 파일의 내용을 잘라낼 수 있고, `>>`는 뒤에 덧붙인다. `2>`는 표준오류를 따로 보낸다. **파이프** `|`는 앞 프로세스의 표준출력을 뒤 프로세스의 표준입력에 연결한다. 두 프로그램 사이에 자동으로 임시 텍스트 파일을 만드는 방식이 아니라 커널이 제공하는 바이트 흐름을 사용한다.

```bash
printf 'alpha\nbeta\n' | wc -l
```

여기서 printf는 두 줄을 표준출력으로 보내고 wc는 표준입력에서 줄 수를 센다. wc는 입력이 키보드에서 왔는지 다른 프로그램에서 왔는지에 의존하지 않고 같은 일을 한다. 이 성질 때문에 작은 도구를 연결할 수 있다. 다만 프로그램들이 나누는 것은 의미가 정해진 표 자체가 아니라 바이트이므로 열 구분·언어·헤더가 바뀌면 해석도 달라진다.

monitoring의 `{ ...; } | wall`은 여러 출력 명령을 묶어 그 출력을 wall 한 번에 보낸다. 오류는 기본적으로 stderr로 나가므로 `|`만으로 다음 프로그램의 입력이 되지 않는다. 출력과 오류를 구별하면 정상 보고서와 실패 원인을 따로 볼 수 있다.

## 명령에 전달될 인자는 셸 해석을 거친다

**인용(quoting)**은 공백이나 특수문자가 셸 문법으로 해석되는 범위를 제어한다. 경로에 공백이 있을 때 하나의 인자로 유지하는 데 필요하다. **확장(expansion)**은 변수 값·명령 결과·파일 이름 패턴 등을 실제 인자에 반영하는 과정이다. 작은따옴표는 내용을 문자 그대로 유지하는 데 쓰이고 큰따옴표 안에서는 변수 등의 일부 확장이 일어나면서 공백 분리를 막는다. 복사한 명령의 따옴표를 임의로 없애면 대상 경로나 인자 수가 달라질 수 있다.

**명령 치환(command substitution)**은 명령의 출력을 다른 명령의 인자 구성에 사용하는 기능이다. 파이프가 프로그램 사이에 스트림을 연결하는 것과 달리, 셸이 먼저 결과를 받아 명령줄을 구성하는 데 쓴다. **글로브(glob)**는 `*.log`처럼 파일 이름 패턴을 현재 파일 목록으로 확장하는 방식이다. 텍스트 내용의 패턴을 찾는 정규 표현식과 문법·적용 대상이 다르다. monitoring 안의 값 계산도 어떤 프로그램의 출력이 어느 시점에 문자열로 들어오는지 보면 이해하기 쉽다.

## 환경변수와 종료 상태

**변수**는 셸이 이름으로 보관하는 값이다. 그중 자식 프로그램에 전달하도록 내보낸 것이 **환경변수**다. `PATH`는 명령 이름에 슬래시가 없을 때 실행 파일을 찾을 디렉터리 목록이다. `HOME`은 홈 경로, `LANG`·`LC_ALL`은 프로그램의 언어·숫자 표현 등에 영향을 준다. 현재 디렉터리와 PATH는 별개이므로 현재 폴더의 스크립트를 실행할 때 `./monitoring.sh`처럼 경로를 쓰는 이유가 생긴다.

cron의 환경은 로그인 셸의 환경과 같지 않다. 이 프로젝트는 예약에 PATH와 스크립트의 절대 경로를 명시한다. monitoring에서 `LC_ALL=C`를 사용하는 부분은 특정 도구의 출력 언어를 고정해 `Mem:`·`total` 같은 필드를 같은 기준으로 읽기 위해서다. 한 프로그램 앞에 지정한 환경값은 그 실행 범위에 적용되며 시스템 언어 전체를 바꾸는 것이 아니다.

프로그램은 종료하면서 **종료 상태(exit status)**라는 작은 정수를 돌려준다. 보통 0은 성공이고 0이 아니면 실패나 별도 조건이다. `grep`의 1은 일치하는 항목이 없다는 뜻이고, DNF의 업데이트 조회는 업데이트가 있을 때 100을 돌려줄 수 있다. 숫자의 의미는 도구 계약을 따라 읽어야 한다.

Bash의 파이프 종료 상태는 기본적으로 마지막 명령의 결과다. 앞 명령이 실패해도 뒤의 `wc`가 빈 입력을 정상 집계하면 전체가 0으로 끝날 수 있다. 그래서 보고서가 출력됐다는 사실만으로 모든 수집이 성공했다고 볼 수 없다. `pipefail`은 이런 판단을 바꾸는 옵션이지만 그 자체가 모든 오류를 자동 복구하지는 않는다. 현재 스크립트의 동작을 이해하는 것과 오류 처리 설계를 새로 추가하는 것은 별도 작업이다.
