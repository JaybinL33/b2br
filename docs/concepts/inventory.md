# 개념 색인

[전체 지도](../concepts.md)

16개 장의 설명을 **331개 찾아보기 항목**으로 묶었다. 영문 별칭은 따로 세지 않았고, 호스트·게스트처럼 함께 비교하는 개념과 PAM의 네 처리 단계 등은 한 항목으로 묶었다. 여러 장에 등장하는 지연 시간·의존성도 중복 항목을 만들지 않았다. 항목 수가 지식의 완전성을 뜻하지는 않으며, 각 링크의 본문에서 의미·목적·작동 관계와 예를 읽는다.

한 항목에 여러 개념이 묶여 있거나 여러 장의 설명이 연결될 수 있다. 개별 명령을 실행했다는 목록이나 실습 완료 체크리스트가 아니다.

## 설명 범위 검토

| 연결 | 본문에서 확인할 설명 |
|---|---|
| 실행 환경 | OS·커널·배포판에서 VM·컨테이너·하이퍼바이저로 이어지며 독립 커널과 공유 커널을 구분한다. |
| 실행과 자원 | 프로그램·프로세스·스레드, 스케줄링·IPC·동기화와 가상 메모리·캐시·swap을 연결한다. |
| 저장과 부팅 | 파일 이름·inode와 블록 장치를 구분하고 파티션→LUKS→LVM→파일시스템→마운트, 펌웨어→커널→서비스를 설명한다. |
| 접속과 권한 | IP·포트·NAT·DNS, SSH의 서버 확인과 사용자 인증, PAM·파일 권한·방화벽·MAC의 역할을 구분한다. |
| 유지 관리 | 패키지 의존성과 갱신, 설정 적용과 예약·시간, 로그·수치·요청 경로, 백업·복원 목표와 무결성을 연결한다. |

짧은 정의만으로 의미가 끝나지 않도록 주변 문장에서 목적·작동 방식·차이와 예를 함께 설명했다. 예를 들어 PV·VG·LV는 세 약어를 풀어 쓰는 데 그치지 않고 공간을 풀로 관리하는 이유와 VG 여유가 파일시스템 여유와 다른 수치 예를 포함한다. 깊은 개념도 본문에 남기되 읽는 순서와 반복해서 읽을 깊이를 조절한다.
